# Complexité algorithmique (Big O)

La notation **Big O** (<Vocab>Big O notation</Vocab>) décrit comment le temps (ou la mémoire) d'un algorithme évolue quand la taille des données grandit.

## Les classes les plus courantes

| Notation | Nom | Exemple |
|----------|-----|---------|
| \( O(1) \) | Constant | Accès à un index de tableau |
| \( O(\log n) \) | Logarithmique | Recherche binaire |
| \( O(n) \) | Linéaire | Parcourir une liste |
| \( O(n \log n) \) | Linéarithmique | Tri efficace (merge sort, quicksort moyen) |
| \( O(n^2) \) | Quadratique | Double boucle imbriquée |
| \( O(2^n) \) | Exponentiel | Sous-ensembles, certains backtracking |

## Exemple concret

```python
# O(n²) — à éviter sur de gros volumes
def has_duplicate_naive(arr):
    for i in range(len(arr)):
        for j in range(i+1, len(arr)):
            if arr[i] == arr[j]:
                return True
    return False

# O(n) — beaucoup mieux
def has_duplicate_smart(arr):
    seen = set()
    for x in arr:
        if x in seen:
            return True
        seen.add(x)
    return False
```

<Callout type="math" title="Règle pratique">
Quand \( n \) double :
- \( O(n) \) → temps ×2
- \( O(n^2) \) → temps ×4
- \( O(2^n) \) → explosion
